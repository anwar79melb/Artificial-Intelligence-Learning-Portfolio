# Tutorial 06: Modern CNN Architectures - GoogLeNet and ResNet

## Overview

In the previous tutorial, we explored AlexNet and VGGNet, two landmark Convolutional Neural Network (CNN) architectures that significantly improved image classification performance.

As CNNs became deeper, researchers encountered several challenges:

- Increasing computational cost
- Large numbers of parameters
- Slower training
- Vanishing gradients
- Overfitting

To overcome these limitations, new architectures were developed. This tutorial introduces two of the most influential CNN architectures:

- GoogLeNet (Inception Network)
- ResNet (Residual Network)

These architectures improved both efficiency and accuracy, enabling neural networks to become significantly deeper while maintaining strong performance.

# 1. The Evolution of CNN Architectures

As computer vision matured, CNN architectures became increasingly deeper.

| Architecture | Year | Depth |
|-------------|------|--------|
| AlexNet | 2012 | 8 Layers |
| VGG16 | 2014 | 16 Layers |
| GoogLeNet | 2014 | 22 Layers |
| ResNet | 2015 | 152 Layers |

The trend was clear:

```text
Deeper Networks
        ↓
Better Feature Learning
        ↓
Higher Accuracy
```

However, increasing depth introduced new optimization challenges.

---

# 2. The Problem with Deep Networks

Increasing network depth is not always beneficial.

Challenges include:

### Computational Cost

More layers require:

- More memory
- More computations
- Longer training times

---

### Overfitting

Larger networks have more parameters and can memorize training data.

---

### Vanishing Gradients

Gradients become extremely small as they propagate backwards through the network.

Result:

```text
Early Layers Learn Slowly
```

or stop learning altogether.

---

### Exploding Gradients

Gradients become excessively large.

Result:

```text
Unstable Training
```

---

# 3. GoogLeNet

GoogLeNet was introduced by:

```text
Christian Szegedy and colleagues
```

in the paper:

```text
Going Deeper with Convolutions
```

It won the:

```text
ILSVRC 2014
```

competition.

---

## Key Goals

GoogLeNet focused on:

✅ Greater depth

✅ Higher efficiency

✅ Fewer parameters

✅ Lower computational cost

---

## Comparison with AlexNet

AlexNet:

```text
~60 Million Parameters
```

GoogLeNet:

```text
~4 Million Parameters
```

Despite being much deeper, GoogLeNet was significantly more efficient.

---

# 4. The Inception Module

The most important innovation in GoogLeNet is the:

```text
Inception Module
```

Instead of using a single convolution size:

```text
3×3
```

the network processes the same input using multiple filter sizes simultaneously.

---

## Parallel Processing

The input is sent through:

```text
1×1 Convolution
       ↓

3×3 Convolution
       ↓

5×5 Convolution
       ↓

Pooling
```

All outputs are then combined.

---

## Why Use Multiple Filters?

Different visual features require different receptive fields.

### Small Filters

Capture:

```text
Edges

Textures

Fine Details
```

---

### Large Filters

Capture:

```text
Shapes

Objects

Global Context
```

The Inception Module learns features at multiple scales simultaneously.

---

# 5. Computational Challenge

Although multiple parallel filters improve feature extraction, they greatly increase computation.

Consider:

```text
Input Volume

28 × 28 × 256
```

Applying many filters directly becomes computationally expensive.

This motivated a more efficient design.

---

# 6. 1×1 Convolutions

GoogLeNet introduced widespread use of:

```text
1 × 1 Convolutions
```

---

## Purpose

A 1×1 convolution:

- Preserves width and height
- Reduces depth (channels)
- Reduces computation

---

## Example

Input:

```text
56 × 56 × 64
```

1×1 convolution:

```text
32 Filters
```

Output:

```text
56 × 56 × 32
```

Spatial dimensions remain unchanged, but the number of channels decreases.

---

# 7. Bottleneck Layers

A bottleneck layer performs:

```text
Dimension Reduction
```

before expensive convolutions.

---

## Workflow

Instead of:

```text
Input
    ↓
5×5 Convolution
```

we use:

```text
Input
    ↓
1×1 Convolution
    ↓
5×5 Convolution
```

This dramatically reduces:

- Parameters
- Memory usage
- Computation

---

## Advantages

✅ Faster training

✅ Lower memory requirements

✅ More efficient networks

✅ Reduced overfitting

---

# 8. Inception Module with Dimension Reduction

The improved Inception Module contains:

```text
1×1 Convolution
       ↓

1×1 → 3×3

1×1 → 5×5

Pooling → 1×1
```

Each branch extracts different information.

Outputs are concatenated into one feature volume.

---

# 9. GoogLeNet Architecture

GoogLeNet is built by stacking multiple Inception Modules.

High-level structure:

```text
Input
      ↓
Convolution
      ↓
Pooling
      ↓
Inception Modules
      ↓
Average Pooling
      ↓
Fully Connected Layer
      ↓
Softmax
```

---

# 10. Auxiliary Classifiers

Training very deep networks often causes gradients to weaken.

GoogLeNet introduced:

```text
Auxiliary Classifiers
```

within the network.

---

## Purpose

Provide additional gradient signals during training.

Benefits:

✅ Reduced vanishing gradients

✅ Improved optimization

✅ Faster convergence

---

# 11. Why GoogLeNet Was Successful

GoogLeNet demonstrated that:

```text
Efficient Design
>
Simply Adding More Parameters
```

Key innovations included:

- Inception Modules
- Bottleneck Layers
- 1×1 Convolutions
- Auxiliary Classifiers
- Batch Normalization

# 12. ResNet

Although GoogLeNet was highly successful, researchers still wanted even deeper networks.

This led to:

```text
Residual Networks (ResNet)
```

introduced by:

```text
Kaiming He and colleagues
```

in 2015.

---

## Major Achievement

ResNet won:

```text
ILSVRC 2015
```

with:

```text
3.57% Top-5 Error
```

outperforming previous architectures.

---

# 13. The Degradation Problem

Researchers observed a surprising phenomenon.

When networks became deeper:

```text
Training Error Increased
```

instead of improving.

This became known as:

```text
The Degradation Problem
```

---

## Important Observation

A 56-layer network sometimes performed worse than a 20-layer network.

Not because of overfitting.

But because:

```text
Optimization Became Difficult
```

---

# 14. Residual Learning

ResNet introduced a completely new idea.

Instead of learning:

```text
H(x)
```

directly,

the network learns:

```text
F(x)
=
H(x) - x
```

called the:

```text
Residual Mapping
```

---

## Final Output

```math
H(x)
=
F(x)
+
x
```

This simple modification transformed deep learning.

---

# 15. Skip Connections

The key component of ResNet is the:

```text
Skip Connection
```

also called:

```text
Shortcut Connection
```

---

## Standard CNN

```text
Input
      ↓

Layers
      ↓

Output
```

---

## Residual Block

```text
Input
      ↓

Convolution
      ↓

ReLU
      ↓

Convolution
      ↓

Add Original Input
      ↓

Output
```

The original input bypasses several layers.

---

# 16. Why Skip Connections Work

Skip connections help:

✅ Preserve information

✅ Improve gradient flow

✅ Reduce vanishing gradients

✅ Enable very deep architectures

✅ Improve optimization

---

# 17. Residual Block

A standard Residual Block contains:

```text
Input
      ↓
3×3 Conv
      ↓
ReLU
      ↓
3×3 Conv
      ↓
Addition
      ↓
Output
```

The addition step combines:

```text
F(x)
+
x
```

---

# 19. Bottleneck Residual Blocks

For deeper ResNets:

```text
50+

101+

152 Layers
```

a bottleneck design is used.

---

## Structure

```text
1×1 Convolution
        ↓
3×3 Convolution
        ↓
1×1 Convolution
```

---

## Purpose

The first layer:

```text
Compresses Features
```

The middle layer:

```text
Processes Features
```

The last layer:

```text
Expands Features
```

This makes extremely deep networks computationally feasible.

---

# 20. Training ResNet

Several techniques contributed to ResNet's success.

---

## Batch Normalization

Applied after convolution layers.

Benefits:

- Stable gradients
- Faster convergence

---

## Weight Initialization

Proper initialization improves optimization.

---

## SGD with Momentum

Commonly used:

```text
Momentum = 0.9
```

to accelerate learning.

---

## Learning Rate Scheduling

Learning rates were gradually reduced during training.

---

## Weight Decay

Used as a regularization technique.

---

# 21. Why ResNet Changed Deep Learning

Before ResNet:

```text
Very Deep Networks
=
Difficult to Train
```

After ResNet:

```text
Hundreds of Layers
=
Practical
```

ResNet demonstrated that extremely deep architectures could achieve superior performance when optimization challenges were properly addressed.

---

# 22. Transfer Learning with ResNet

Modern practice rarely trains ResNet from scratch.

Instead:

```text
Load Pretrained ResNet
```

trained on:

```text
ImageNet
```

and use it as a feature extractor.

---

## Workflow

```text
Load Pretrained ResNet
         ↓
Freeze Convolution Layers
         ↓
Add New Classification Head
         ↓
Train New Layers
         ↓
Fine-Tune if Necessary
```

---

# 23. ResNet in TensorFlow

TensorFlow provides pretrained models through:

```python
tf.keras.applications
```

Example:

```python
from tensorflow.keras.applications import ResNet152
```

Load model:

```python
base_model = ResNet152(
    weights="imagenet",
    include_top=False
)
```

---

## Why Freeze Layers?

The pretrained layers already contain valuable visual features such as:

```text
Edges

Textures

Shapes

Objects
```

These do not need to be relearned.

---

# 24. GoogLeNet vs ResNet

| Feature | GoogLeNet | ResNet |
|----------|-----------|---------|
| Key Idea | Inception Modules | Residual Learning |
| Main Goal | Efficiency | Train Very Deep Networks |
| Depth | 22 Layers | Up to 152+ Layers |
| Uses 1×1 Convolution | Yes | Yes (Bottleneck Blocks) |
| Uses Skip Connections | No | Yes |
| ImageNet Winner | 2014 | 2015 |
| Transfer Learning Support | Excellent | Excellent |
